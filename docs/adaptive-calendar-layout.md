# 화면 비율에 독립적인 달력 판독 개선

## 확인한 문제

앞선 메모리 제한 수정은 화면 배치 문제를 해결하지 않았다. 기존 판독기는 사진 전체 폭을 7등분하고, 근무 원 크기·위치를 열 폭으로 추정했으며, 제목을 화면 높이의 고정 구간에서 찾았다. 격자 탐지 실패 시 iPhone 비율로 좌표를 추정했다.

공개 비식별 캡처의 숫자와 근무 표시를 그대로 두고 셀 폭·높이, 패널 위치, 여백만 바꾸는 재현 자료를 만들었다. 기존 코드에서 새 배치 테스트 6개가 모두 실패했다. 폴드형 넓은 셀과 가로 화면은 셀 비율 제약 때문에 격자를 찾지 못했고, 옆 패널·여백은 전체 화면 폭을 쓰는 좌표 계산을 깨뜨렸다. 일반 세로 배치에서도 이동한 제목을 읽지 못했다. 실제 삼성 기기 캡처를 확보한 것은 아니므로 제조사·모델별 검증으로 해석하지 않는다.

## 변경

- 이미지 어디에 있든 반복되는 가로 경계선과 내부 세로 경계선을 함께 확인해 실제 달력 좌우·상하 범위를 찾는다.
- 셀을 실제 달력 범위로 나눈다. 세로로 긴 iPhone 셀만 허용하던 조건을 제거했다.
- 셀 안의 반복되는 원형 색상 덩어리로 근무 표시 위치와 크기를 추정한다. 셀만 넓어지거나 표시가 작아져도 분리해 처리한다. 전부 휴무인 달은 반복되는 빨간 휴무 표시를 사용한다.
- 날짜 영역의 크기도 관측한 표시 크기를 반영한다. 제목은 달력 바로 위에서 같은 줄에 있는 `YYYY.MM` 형태를 찾는다. 선택한 달에 맞추어 제목 후보를 고르지 않는다.
- 어두움 검사와 중복 사진 지문은 캡처 전체가 아닌 실제 달력 범위를 사용한다.
- iPhone 비율로 좌표를 추정하는 대체 경로는 삭제했다. 격자나 근무 표시가 불확실하면 오류/직접 확인으로 보내고, 다른 달·잘림·낮은 확신도 검사는 유지한다.
- 해상도 제한, 두 장 순차 디코딩, 로컬 분석·개인 이미지 비전송 원칙은 유지한다.

## 재현 범위

단순히 원본을 다른 크기로 늘린 이미지가 아니라, 날짜·원 모양을 유지한 채 각 셀을 재배치한 자료를 사용한다.

- 긴 세로형, 폴드형 넓은 셀, 가로형의 5주 달력
- 옆 패널에 있는 달력, 좌우 여백
- 글자/표시 크기 75%·130%, 근무 표시의 세로 위치 이동
- 전체 휴무, 검은 외부 패널
- 같은 달력의 외부 여백 변경 시 같은 사진 지문 유지
- 잘린 달력과 일반 가로 구분선 목록은 거부
- 기존 iPhone 비식별 캡처 12종, 5주·6주 달력 및 36개월 월 검증 유지
- PNG/JPEG/WebP, EXIF, MIME/확장자, 대체 디코딩 기존 회귀 검사 유지

## 지원 한계

실제 Galaxy/Fold 기기와 모든 오늘근무 설정을 검증한 것은 아니다. 현재는 밝은 배경의 7열 월간 격자와 A/B/C 색상 원·휴 표시라는 형식을 사용한다. 격자 없는 테마, 전혀 다른 글꼴·근무 기호, 카메라 원근 왜곡, 여러 달력이 한 이미지에 있는 배치는 보장하지 않는다. 확신이 낮은 입력을 무조건 통과시키지 않는다.

## 최종 검증 결과

- 타입 검사·프로덕션 빌드: 통과.
- 단위 검사: 95 통과, 기존 비공개 fixture 등의 조건으로 3 생략.
- Chromium 전체 E2E: 51 통과, 비공개 원본 검사 1 생략.
- WebKit: 새 배치·형식·등록·월 검증 26 통과, 비공개 원본 검사 1 생략. 앞선 수정 전/후 모두 실패한 WebKit 오프라인 새로고침 검사는 이번 실행 대상에서 명시적으로 제외했다.
- 판독 자료는 합성/비식별 이미지다. 실제 Galaxy/Fold 기기 확인은 별도로 남아 있다.
