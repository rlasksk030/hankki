# Android 캡처 판독 점검 (2026-09-29)

## 범위와 확인 수준

- 기준: `origin/main`의 `e67925b`, 개발 브랜치 `fix/android-screenshot`.
- 실제 실패한 Android 캡처는 제공되지 않았다. 따라서 사용자 기기에서의 원인 확정·완전 해결을 주장하지 않는다.
- 비식별 기존 캡처를 변형한 테스트와 메모리 할당 실패를 모의한 테스트로 확인 가능한 부분만 수정했다.

## 처리 흐름과 진단

1. `Onboarding.tsx`: `accept="image/*"` 파일 선택. 확장자/MIME 검사로 거부하지 않으며 `capture` 강제 속성이 없다. 실제 Android 갤러리·카메라 UI는 이번 자동화로 검증할 수 없다.
2. `App.tsx` → `loadImage.ts`: Blob을 `createImageBitmap`으로 디코딩하고 실패하면 `Image.decode()`로 재시도한다. Canvas에서 RGBA를 얻는다. 업로드 요청은 없고 모두 로컬 처리다.
3. `grid.ts`: 가로선을 탐지한다. 실패하면 iPhone용 높이 비율(0.132~0.8765)을 적용한다. 셀 높이/폭 조건과 화면 전체 폭을 7등분하는 가정이 있다.
4. `analyze.ts`: 원 색상으로 A/B/C와 휴무를 읽고 날짜 잉크로 달력 배치를 검사한다. 일반 OCR이 아니다.
5. `title.ts`: 화면 높이 5~11.5%의 숫자를 템플릿으로 비교한다. Android 앱의 제목 위치·폰트·달력 배치가 다르면 실패할 가능성이 있으나 실제 입력 없이 조건을 임의 완화하지 않았다.
6. 어두움, 잘림, 달 불일치, 낮은 확신도를 각각 거부한다. ‘다시 캡처’ 문구만으로 어느 조건인지 특정할 수 없다. 디코딩 실패는 ‘사진을 불러오지 못했어요’로 별도 안내한다.

## 재현된 문제와 수정

- 기존 코드는 두 이미지를 동시에 원본 크기로 디코딩하고, Canvas 및 RGBA 버퍼도 원본 크기로 만든다. 2880×6400 RGBA 한 벌은 약 70.3MiB다.
- 픽셀 읽기에서 예외가 발생하면 Canvas 크기를 0으로 돌리는 처리가 실행되지 않았다.
- 4백만 픽셀 이상 할당을 거부하는 모의 환경에서 기존 코드는 실패했다. 이 값은 테스트 조건이며 특정 Android 브라우저의 실제 제한이라는 뜻은 아니다.
- 분석 Canvas는 비율을 유지하면서 폭 1440px 이하·4백만 픽셀 이하로 제한한다. 1179×2556 iPhone 이미지는 크기를 유지한다.
- 두 장을 순서대로 처리하고 Canvas 해제를 `finally`로 이동했다. 일반 디코딩·EXIF 자동 적용 경로와 판독/유효성 기준은 유지했다.
- 원본 디코더 자체와 화면 미리보기의 메모리까지 제한하는 수정은 아니다. 극단적으로 큰 이미지가 모든 기기에서 성공한다는 보장은 없다.

## 재현 테스트

- PNG/JPEG/WebP × 720/1080/1440px, 위아래 여백 변형 3종: 기존 코드에서도 12개 통과. 테스트한 범위의 형식·해상도·여백은 원인으로 재현되지 않았다.
- 새 단위 테스트: 큰 Canvas 할당 제한, 실패 시 자원 해제, 일반 iPhone 크기 보존. 수정 전 2개 실패 → 수정 후 통과.
- 새 브라우저 테스트: 고해상도 PNG, JPEG, WebP, 빈 MIME/확장자, 잘못된 MIME/확장자, EXIF orientation=6을 기본 디코딩과 강제 Image fallback에서 각각 검사한다. 실제 파일 입력부터 간편식 7회 결과까지 확인한다.
- 테스트 이미지들은 공개 비식별 fixture에서 메모리 안에서 생성한다. 개인 원본을 추가하거나 서버로 전송하지 않는다.

## 남은 확인

Android 실기기의 브라우저/OS와 실제 근무표 배치를 사용한 확인은 미완료다. 같은 문제가 남으면 오류 안내 전문 및 실제 캡처를 로컬에서 확인해야 격자·제목·원 위치 중 실패 지점을 특정할 수 있다. 현재 변경은 메모리 처리 보강이며 Android 전용 판독 문제의 확정 수정으로 해석하면 안 된다.

EXIF 기본 동작 참고: https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap
